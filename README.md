# Ping Pong

Минималистичный настольный Pong для Arch Linux / Hyprland и macOS. C++17, SDL3 и FreeType; на Linux используется Wayland с запасным вариантом X11, на Mac — нативное окно Cocoa. Тёмное поле занимает всю клиентскую область окна. Игрок слева, бот справа; касание мячом левой или правой границы приносит очко сопернику.

## Сборка и запуск на Arch

```sh
sudo pacman -S --needed base-devel cmake sdl3 freetype2
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/ping-pong
```

Шрифт уже включён в проект, интернет при сборке и запуске не нужен. Папка `assets` должна оставаться рядом с собранным исполняемым файлом; CMake копирует её автоматически. Запуск возможен из любой рабочей папки.

## macOS: Apple Silicon и Intel

Для macOS создаётся самостоятельное приложение `Ping Pong.app`: SDL, FreeType и шрифт уже внутри, устанавливать их игроку не нужно. Сборка рассчитана на macOS 12 и новее; автоматические проверки выполняются на macOS 15 для обеих архитектур.

Готовые ZIP-архивы доступны в **Artifacts** успешного запуска [macOS в GitHub Actions](https://github.com/samestump/ping-pong/actions/workflows/macos.yml): `arm64` для Apple Silicon (M1 и новее), `x86_64` для Intel. Для скачивания артефакта потребуется вход в GitHub. Распакуйте архив приложения и перенесите `Ping Pong.app` в «Программы».

Для сборки на Mac:

```sh
xcode-select --install
brew install cmake
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 3
open "build/Ping Pong.app"
```

При первой конфигурации CMake скачивает закреплённые версии SDL и FreeType и проверяет SHA-256. Homebrew нужен только как удобный способ установить CMake, если его ещё нет. При запуске интернет не требуется.

Управление и правила совпадают с Linux: прокрутка двумя пальцами, `1–3`, `R`, `Q`, `Esc`, `A`; поддерживаются Retina, пауза при изменении размера и сохранение геометрии. macOS использует свой каталог настроек, возвращаемый SDL, обычно `~/Library/Application Support/ping-pong/ping-pong/window-size.txt`. Вызовов `hyprctl` на Mac нет.

Приложение имеет локальную ad-hoc подпись, но не подпись Apple Developer ID и не notarization. При блокировке скачанной сборки используйте штатное «Всё равно открыть» в настройках macOS для приложения, которому доверяете. Подробности сборки, проверки и ограничений — в [MACOS.md](MACOS.md).

## Управление

| Действие | Управление |
|---|---|
| Перемещение левой ракетки | Вертикальная прокрутка тачпада двумя пальцами или колесо |
| Лёгкий / средний / сложный бот | `1` / `2` / `3` |
| Сброс счёта и новая игра с текущей сложностью | `R` |
| Пауза / продолжение и подсказки управления | `Esc` |
| Автоматическая игра левой ракеткой | `A` |
| Выход | `Q` |

Клавиши определяются по физическому расположению, поэтому работают и в русской раскладке. Направление прокрутки следует системной настройке natural scrolling. Дробные движения тачпада не округляются; перемещение ракетки сглаживается. По умолчанию выбран средний бот. Сложность меняется немедленно без сброса текущего розыгрыша. В режиме `AUTO` обе ракетки используют одинаковый алгоритм и выбранную сложность. `A` возвращает ручное управление без скачка ракетки; `R` сохраняет автоматический режим. Подсказки видны в меню паузы `Esc`, а во время автоматической игры внизу отображается серая надпись `AUTO`. Курсор скрывается внутри окна и возвращается при выходе за его границы.

## Окно и масштаб

Масштаб определяется через SDL по плотности пикселей и настройке масштаба монитора, включая дробный масштаб Wayland. Размер окна меняет только площадь поля: размеры мяча, ракеток, текста и скорости в логических единицах постоянны. При переносе на монитор с другим масштабом изображение подстраивается под него.

При событиях изменения размера симуляция приостанавливается и продолжается через 180 мс после последнего события. Это эвристика окончания изменения размера: если задержать перетаскивание без новых событий, игра продолжится. При сужении поля объекты перемещаются внутрь новых границ без начисления гола. Потеря фокуса и сворачивание также ставят игру на паузу. Минимальный размер окна — 320 × 240.

Размер окна сохраняется через 180 мс после последнего изменения и при выходе. Используются размеры из событий композитора; запись файла заменяется атомарно. При следующем запуске размер восстанавливается. Старое ошибочное значение 320 × 240 автоматически заменяется базовым размером; новый формат позволяет намеренно сохранять и минимальный размер. Файл настроек: `$XDG_DATA_HOME/ping-pong/ping-pong/window-size.txt` (обычно `~/.local/share/ping-pong/ping-pong/window-size.txt`). Проверочные запуски не изменяют настройки. В Hyprland игра при запуске переводит своё окно в floating и применяет сохранённый размер через `hyprctl` (Lua-интерфейс современных версий Hyprland). Команды адресуются только PID игры; конфигурация Hyprland не меняется. Это необходимо, поскольку тайлинговый композитор может игнорировать запрос размера SDL. В других окружениях используется обычное восстановление SDL. Базовый размер — 960 × 600.

Физика обновляется с частотой 240 Гц независимо от кадров; отрисовка использует VSync, если драйвер его поддерживает. Боты отличаются задержкой реакции, предельными скоростью и ускорением и точностью предсказания отскоков. Они плавно разгоняются и тормозят; ошибка прицеливания выбирается один раз на подлёт мяча, а при ожидании ракетка спокойно останавливается в центре. Скорость мяча постепенно растёт до ограниченного максимума.

## Проверки

```sh
ctest --test-dir build --output-on-failure
./build/ping-pong --smoke-test
```

CTest проверяет физику, голы, смену сложности, сброс, дробную прокрутку, уменьшение поля и длительную симуляцию. Проверка сохранения запускает приложение дважды с отдельным файлом настроек: восстанавливает 1234 × 789, меняет на 1100 × 700, закрывает и проверяет повторное открытие в 1100 × 700. Отдельная проверка SDL автоматически отправляет события клавиатуры, прокрутки и изменения размера; в CTest она выполняется без экрана. Вторая команда кратко открывает настоящее окно для проверки текущего видеодрайвера.
